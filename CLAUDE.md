## Project Overview

`electron-pos-printer` is a TypeScript library for thermal POS printer support in Electron applications. It supports 58mm and 80mm thermal printers with ESC/POS commands.

## Build Commands

```bash
npm run build      # Build the package (tsup)
npm run dev        # Watch mode for development
npm run test       # Run tests (vitest)
npm run test:run   # Run tests once
npm run typecheck  # TypeScript type checking
```

## Architecture

### Directory Structure
- `src/types/` - TypeScript interfaces and type definitions
- `src/commands/` - ESC/POS command constants and builders
  - `esc-pos.ts` - raw command bytes (`Commands`)
  - `escpos-builder.ts` - converts `PrintContent[]` to an ESC/POS byte stream
  - `codepage.ts` - text encoding pipeline (normalize, transliterate, encode)
  - `codepage-tables.ts` - auto-generated byte-to-Unicode tables for each
    supported codepage; **do not edit by hand**, regenerate with
    `node scripts/generate-codepages.mjs` (source: the Unicode Consortium's
    vendor mapping files)
- `src/printer/` - Printer detection and raw printing (cross-platform)
- `src/utils/` - Formatting utilities, HTML builder, hex-dump debug helper, and ReceiptBuilder class
- `src/electron/` - Electron IPC integration (main, preload, renderer)
- `example/` - Working Electron example app for testing

### Key Components

**ReceiptBuilder** (`src/utils/receipt-builder.ts`): Fluent API for building receipts with support for:
- Text formatting (bold, underline, alignment, sizes)
- Tables with automatic column width calculation
- Barcodes and QR codes
- Currency formatting
- Receipt templates via `fromData()`

**ESC/POS Builder** (`src/commands/escpos-builder.ts`): Converts PrintContent to raw ESC/POS bytes

**dumpESCPOS** (`src/utils/hex-dump.ts`): Renders a raw ESC/POS byte stream as annotated, human-readable text (commands, control codes, decoded text) for debugging without a physical printer

**Raw Printer** (`src/printer/raw-printer.ts`): Cross-platform raw printing:
- Linux/macOS: `lp -d <printer> -o raw` (CUPS)
- Windows: PowerShell with .NET RawPrinterHelper (winspool.drv)

**Electron Integration**:
- Main process: `setupPrinterIPC()` registers IPC handlers. Each print request
  is dispatched to the raw or HTML branch based on `config.mode` (`'raw'`
  default, or `'html'`); the HTML branch needs a `BrowserWindow`, the raw
  branch does not
- Preload: `exposePosPrinterAPI()` exposes safe API to renderer
- Renderer: `PosPrinter` class and `createPosPrinter()` factory

### Encoding pipeline

Text destined for a thermal printer runs through a fixed order, implemented in
`src/commands/codepage.ts`:

```
text -> NFC normalize -> transliterate -> layout -> encode
```

`normalizeForCodepage()` performs the first two steps; its output has the
property that every character maps to exactly one byte in the target
codepage. Layout arithmetic (column padding in tables, line-character
repetition) runs on that normalized text, never on raw input — an ellipsis
`…` expands to three characters `...` and an unencodable character collapses
to a single `?`, so measuring raw text would shift every column after it.
Encoding to bytes happens last, in `encodeText()`.

### Paper Width Support
- 58mm: 32 characters per line
- 80mm: 48 characters per line
- Both can be overridden with `charsPerLine` in `PrinterConfig` or in the
  options passed to `buildESCPOSData()`, for printers that are neither 32 nor
  48 columns (42-column printers are a common case)

### IPC Channels
- `pos-printer:get-printers` - Get available printers
- `pos-printer:print` - Print content

## Code Patterns

- Uses tsup for bundling (CJS + ESM + DTS)
- Electron is a peer dependency (>=28.0.0)
- All printer operations are async
- Raw ESC/POS printing for thermal printers
- Cross-platform support (Linux, macOS, Windows)
